# HR

**Mission.** Build the org: roles, JDs, and — as ZYNTH grows — hiring and onboarding real people into these seats.

**Reports to.** CEO

**Responsibilities.**
- Keep the org chart + JDs current (this vault)
- Define what 'good' looks like per role
- Run hiring when a seat needs a human
- Onboard using the SOPs

**KPIs.**
- Seats filled vs plan
- Time-to-productive for new hires
- SOP coverage

**Runs on today (AI).** `agents/hr.py` + this ZYNTH-OS vault.

**To hire a human.** You (MD) + this documentation; a people/ops hire later.

## Operating Charter

| Operating element | Role contract |
| --- | --- |
| **Mission** | Role clarity, capability building, fair people systems and workforce planning. |
| **Core inputs** | Approved organisation plan, capacity/quality needs, role evidence, manager feedback, budget and policy constraints. |
| **Core outputs** | Role charter, competency/interview scorecard, onboarding/performance plan, development and capacity recommendation. |
| **Cadence** | Monthly talent/capacity review; hiring gates; onboarding 30/60/90 check-ins; performance cycle. |
| **Decision rights** | Recommend roles/processes; founder/authorised leaders make employment, salary and disciplinary decisions. |
| **Escalation** | Escalate sensitive people, safety, discrimination, legal/policy, capability or capacity risks. |

### Quality and Handoff

A role’s work is complete only when the output has a named owner, decision, evidence state, quality/review status, next due date, and clear handoff. Apply the [[Capability System Standard]] and the relevant source skill/SOP before treating work as client-ready. Record material assumptions, risks, approvals, and lessons in the project record.
